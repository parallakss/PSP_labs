## 1. Введение в Express.js

Express.js (или просто Express) — это минималистичный и гибкий веб-фреймворк для Node.js, который предоставляет обширный набор функций для создания веб-приложений и API.

В то время как встроенный модуль `http` в Node.js дает лишь низкоуровневые инструменты для работы с сервером, Express предоставляет удобные абстракции:
- **Роутинг (маршрутизация):** Позволяет легко определять обработчики для URL и HTTP-методов (GET, POST, PATCH, DELETE).
- **Middleware (промежуточные обработчики):** Основа архитектуры Express. Запрос проходит через цепочку функций, которые могут изменять его, логировать, добавлять заголовки (CORS) или завершать обработку.
- **Быстрая обработка JSON:** Инструменты вроде `express.json()` сильно упрощают работу с телом запроса, избавляя от необходимости вручную парсить потоки данных (Streams).

## 2. Сравнение Express.js с чистым Node.js и NestJS

### Express vs Чистый Node.js
В чистом Node.js (используя встроенный модуль `http`) разработчику приходится вручную писать логику парсинга URL-адреса, извлекать параметры, проверять HTTP-методы и собирать тело запроса.
Вместо длинных `if (req.method === 'GET' && req.url === '/stocks')` Express предлагает декларативный подход:
```javascript
// Пример в Express.js
app.get('/stocks', (req, res) => {
    res.json({ message: "Список классов кораблей кораблестроительного производства" });
});
```

### Express vs NestJS
Express является легким инструментом (библиотекой), не навязывающим строгой архитектуры. Разработчик сам выбирает структуру папок и подходы к написанию кода.
NestJS, напротив, является строгим фреймворком корпоративного уровня. Он написан на TypeScript, по умолчанию использует декораторы и концепцию внедрения зависимостей (Dependency Injection).
Для старта разработки и глубокого понимания работы HTTP-серверов «под капотом» Express подходит гораздо лучше.

Инициализация проекта и установка зависимостей выполнялись в директории `example-express`:

## 4. Архитектура приложения кораблестроительное производство

Хотя Express не требует строгой структуры, в данной работе мы использовали **Слоистую архитектуру (Layered Architecture)**, чтобы код был чистым, масштабируемым и легко поддерживаемым.

Структура директорий `src`:
- **`index.js`** — Точка входа. Здесь инициализируется Express, подключаются middleware (парсинг JSON, логирование, CORS) и роуты.
- **`routes/stocks.js`** — Слой маршрутизации. Связывает URL (например, `GET /stocks/:id`) с функциями-контроллерами.
- **`controllers/stocksController.js`** — Слой контроллеров. Извлекает параметры из запроса (`req.params`, `req.body`, `req.query`), вызывает сервисы бизнес-логики и формирует HTTP-ответ.
- **`services/`** — Слой бизнес-логики.
  - `stocksService.js` — Выполняет логику поиска, фильтрации и модификации объектов (карточек классов кораблей).
  - `fileService.js` — Инкапсулирует логику работы с файловой системой (`fs.readFileSync`, `fs.writeFileSync`).
- **`data/stocks.json`** — Слой хранения данных. Имитирует настоящую базу данных.

Поток данных (Data Flow) в нашем приложении выглядит так:
`Клиент (Браузер/Postman)` ➔ `index.js (Middleware)` ➔ `routes/stocks.js` ➔ `stocksController.js` ➔ `stocksService.js` ➔ `fileService.js` ➔ `stocks.json`.

## 5. Реализация REST API для классов кораблей кораблестроительного производства

В рамках работы был создан API для управления карточками классов кораблей кораблестроительного производства (патрульные корабли, фрегаты, Балансировщики нагрузки, Защита от DDoS).

### Файл хранения данных (stocks.json)
Массив содержит объекты с ключами `id`, `src` (ссылка на изображение), `name` (название классов кораблейи) и `description` (подробное описание).
Пример записи:
```json
[
  {
    "id": 1,
    "src": "https://images.unsplash.com/photo-1558494949-ef010cbdcc31...",
    "name": "патрульные корабли (VPS/VDS)",
    "description": "Масштабируемые облачные серверы для ваших проектов. Высокий аптайм и SSD NVMe диски."
  }
]
```

### Бизнес-логика (stocksService.js)
Сервис отвечает за операции CRUD (Create, Read, Update, Delete). При создании новой карточки ID генерируется динамически, находя максимальный ID в массиве и прибавляя к нему единицу:
```javascript
const create = (stockData) => {
    const stocks = fileService.readData(dataFilePath);

    // Генерация безопасного ID
    const newId = stocks.length > 0 ? Math.max(...stocks.map(s => s.id)) + 1 : 1;

    const newStock = { id: newId, ...stockData };
    stocks.push(newStock);

    // Сохранение обновленного массива в файл
    fileService.writeData(dataFilePath, stocks);
    return newStock;
};
```

### Контроллер (stocksController.js)
Контроллер валидирует входящие данные. Если запрашивается несуществующий элемент, он возвращает правильный HTTP-статус `404 Not Found`. При успешном создании (POST) возвращается код `201 Created`.
```javascript
const getStockById = (req, res) => {
    const id = parseInt(req.params.id);
    const stock = stocksService.findOne(id);

    if (!stock) {
        return res.status(404).json({ error: 'Карточка не найдена' });
    }

    res.json(stock);
};
```

## 6. Тестирование API с помощью Postman

Для верификации работы бэкенда использовалась утилита тестирования API Postman:

1. **Получение всех карточек (GET):** Запрос `GET http://localhost:3000/stocks` успешно возвращает массив из 4 объектов кораблестроительного производства.
2. **Получение одной карточки (GET):** Запрос `GET http://localhost:3000/stocks/2` корректно возвращает JSON-объект "Выделенных серверов".
3. **Создание новой классов кораблейи (POST):** Запрос `POST http://localhost:3000/stocks` с телом формата JSON:
   ```json
   {
     "name": "Новая классов кораблейа",
     "description": "Тестовое описание",
     "src": "link"
   }
   ```
   Добавляет элемент в файл `stocks.json` и возвращает созданный объект с присвоенным новым `id: 5`.
4. **Обновление (PATCH) и Удаление (DELETE):** Методы работают штатно. Удаление по ID возвращает статус `204 No Content` при успехе, а обновление успешно модифицирует поля переданного ID.

## 7. Дополнительные реализованные задания

В рамках лабораторной работы код бэкенда был существенно адаптирован и расширен кастомным функционалом, который выходит за рамки базового мануала:

### 7.1 Настройка CORS-политик
Для того чтобы фронтенд-приложение (клиентская часть, написанная на Vanilla JS) могло беспрепятственно отправлять fetch-запросы на порт `:3000`, в главный файл `index.js` был внедрен кастомный `CORS` middleware.
Он разрешает запросы с любых источников (`*`) и корректно обрабатывает предварительные `OPTIONS` запросы браузера.
```javascript
// Настройка CORS для разрешения запросов с фронтенда
app.use((req, res, next) => {
    res.setHeader('Access-Control-Allow-Origin', '*');
    res.setHeader('Access-Control-Allow-Methods', 'GET, POST, PATCH, DELETE, OPTIONS');
    res.setHeader('Access-Control-Allow-Headers', 'Content-Type');

    if (req.method === 'OPTIONS') return res.sendStatus(200);

    next(); // Передача управления следующему middleware
});
```

### 7.2 Продвинутая фильтрация и поиск (Дополнительный Endpoint)
Поскольку в проекте кораблестроительного производства объекты не имеют поля `title` (как в базовом примере), а имеют более сложные поля `name` и `description`, логика контроллеров и сервисов была переписана под поиск именно по этим полям.

В контроллере `stocksController.js` реализован уникальный метод `getStockByDescription`, который позволяет искать классов кораблейи прямо по их описанию:
```javascript
const getStockByDescription = (req, res) => {
    // Получаем описание из параметров URL или строки запроса (query)
    const description = req.params.description || req.query.description;

    // Вызываем сервис, передавая null для name и искомое описание
    const stocks = stocksService.findAll(null, description);

    if (!stocks || stocks.length === 0) {
        return res.status(404).json({ error: 'Классы кораблей с таким описанием не найдены' });
    }

    res.json(stocks);
};
```
Функция `findAll` в сервисе также была доработана, чтобы принимать и обрабатывать второй параметр `description`.

### 7.3 Логирование запросов
Реализован самописный middleware для логирования всех входящих запросов в консоль с указанием точного времени по стандарту ISO, метода и пути:
```javascript
app.use((req, res, next) => {
    console.log(`[${new Date().toISOString()}] ${req.method} ${req.url}`);
    next();
});
```
