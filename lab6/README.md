# Лабораторная работа 6: fetch, Promise и сборка проекта

В папке `lab6` выполнена лабораторная работа по теме асинхронного обмена данными между клиентской частью и сервером. Работа адаптирована под предметную область проекта: производство кораблей и судостроительные карточки.

## Цель работы

Цель лабораторной работы заключается в замене сетевых запросов на современный API `fetch`, использовании `Promise` и `async/await`, а также в настройке сборки клиентского приложения через Vite с последующей раздачей собранных файлов Express-сервером.

## Реализованная структура проекта

Проект разделен на клиентскую и серверную части.

Клиентская часть:

- `index.html` — HTML-точка входа клиентского приложения;
- `main.js` — запуск главной страницы приложения;
- `components/` — переиспользуемые компоненты интерфейса;
- `pages/` — страницы приложения;
- `modules/api.js` — модуль сетевых запросов на `fetch`;
- `modules/stockUrls.js` — модуль формирования URL для API;
- `vite.config.js` — настройки сборки Vite;
- `public/` — собранная клиентская часть после выполнения команды сборки.

Серверная часть:

- `src/index.js` — Express-сервер;
- `src/routes/stocks.js` — маршруты API для карточек кораблей;
- `src/controllers/stocksController.js` — обработчики HTTP-запросов;
- `src/services/stocksService.js` — логика работы с данными;
- `src/services/fileService.js` — чтение и запись JSON-файла;
- `src/data/stocks.json` — хранилище данных карточек кораблей.

## Что реализовано

В работе реализовано получение и обработка карточек судостроительной программы. Каждая карточка описывает объект производства: патрульный корабль, фрегат, судно снабжения или сервисную модернизацию флота.

На стороне клиента реализованы:

- загрузка списка карточек кораблей через `GET /stocks`;
- фильтрация карточек по названию через `GET /stocks?title=...`;
- открытие подробной страницы карточки через `GET /stocks/:id`;
- удаление карточки через `DELETE /stocks/:id`;
- обработка успешных и ошибочных ответов сервера;
- использование `async/await` для асинхронного кода;
- вынесение сетевой логики в отдельный класс `Api`.

На стороне сервера реализованы:

- REST API для работы с карточками;
- маршруты `GET`, `POST`, `PATCH`, `DELETE`;
- проверка обязательных полей при создании карточки;
- возврат статусов `200`, `201`, `204`, `400`, `404`;
- чтение и сохранение данных в JSON-файл;
- раздача собранного фронтенда из папки `public`.

## Использование fetch

Основная замена `XMLHttpRequest` выполнена в файле `modules/api.js`. В нем создан класс `Api`, который содержит методы:

- `get(url)` — получение данных;
- `post(url, data)` — создание записи;
- `patch(url, data)` — обновление записи;
- `delete(url)` — удаление записи;
- `_request(url, options)` — общий метод выполнения запроса через `fetch`.

Метод `_request` ожидает ответ сервера, преобразует JSON-данные и возвращает объект со статусом ответа, признаком успешности и полученными данными. Благодаря этому страницы приложения работают не напрямую с `fetch`, а через единый модуль запросов.

## Работа с URL

Файл `modules/stockUrls.js` отвечает за формирование адресов API. В нем описаны методы для получения списка карточек, получения одной карточки по `id`, создания, обновления и удаления карточки.

Если клиент запущен через Vite на порту `5173`, запросы отправляются на `http://localhost:3001`. Если приложение открыто через Express после сборки, используется относительный путь `/stocks`.

## Сборка проекта

Для сборки клиентской части используется Vite. Команда `npm run build` собирает приложение и помещает результат в папку `public`. После этого Express-сервер раздает собранную страницу и одновременно обслуживает API.

## Проверка работы

Для проверки лабораторной работы используются команды:

```bash
cd lab6
npm run build
npm start
```

После запуска приложение доступно по адресу:

```text
http://localhost:3001
```

API доступно по маршрутам:

```text
GET    /stocks
GET    /stocks?title=Фрегат
GET    /stocks/1
POST   /stocks
PATCH  /stocks/1
DELETE /stocks/1
```

В инструментах разработчика браузера во вкладке `Network` отображаются сетевые запросы типа `fetch`. Это подтверждает, что клиентская часть получает данные с сервера через `fetch`, а не через заранее встроенный HTML.

## Вывод

В результате выполнения лабораторной работы клиентская часть проекта была переведена на `fetch` и `async/await`, сетевые запросы вынесены в отдельный модуль, серверная часть предоставляет REST API для карточек кораблей, а весь проект собирается через Vite и запускается как единое веб-приложение на Express.
