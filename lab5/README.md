## 1. Введение в клиент-серверное взаимодействие

Современные веб-приложения строятся по принципу разделения ответственности. **Фронтенд** (браузерная часть) отвечает только за отрисовку интерфейса и реакцию на действия пользователя. **Бэкенд** (серверная часть) отвечает за бизнес-логику, валидацию и работу с базой данных (в нашем случае — файл `stocks.json`).

Связь между ними происходит по протоколу HTTP с использованием архитектуры **REST API**. Фронтенд отправляет запросы (GET, POST, PATCH, DELETE) на определенные адреса (эндпоинты), а сервер возвращает ответ в формате `JSON`.

## 2. Архитектура интеграции (кораблестроительное производство)

В предыдущих работах класс `MainPage` использовал метод `getData()`, который возвращал статичный массив данных (патрульные корабли, фрегаты и т.д.).
Теперь архитектура изменена:
1. Сервер Express.js запущен на порту `3000` (`http://localhost:3000/stocks`).
2. Клиентский код (запущенный, например, через Live Server на порту `5500`) запрашивает данные с сервера.
3. Фронтенд дожидается ответа сервера и только после этого рендерит компонент `ProductCardComponent`.

## 3. Решение проблемы CORS

**CORS (Cross-Origin Resource Sharing)** — это механизм безопасности браузера, который по умолчанию запрещает веб-странице делать запросы к домену, порту или протоколу, отличному от того, с которого была загружена сама страница.
Поскольку наш клиент крутится на порту 5500, а API — на 3000, браузер заблокирует такие XHR/Fetch запросы.

Для обхода CORS в код бэкенда (`example-express/src/index.js`) был интегрирован специальный Middleware:
```javascript
// Настройка CORS для разрешения запросов с фронтенда
app.use((req, res, next) => {
    // Разрешаем запросы с любых источников (*)
    res.setHeader('Access-Control-Allow-Origin', '*');
    // Разрешаем нужные HTTP методы
    res.setHeader('Access-Control-Allow-Methods', 'GET, POST, PATCH, DELETE, OPTIONS');
    // Разрешаем передачу JSON заголовков
    res.setHeader('Access-Control-Allow-Headers', 'Content-Type');

    // Обработка предварительного preflight-запроса от браузера
    if (req.method === 'OPTIONS') return res.sendStatus(200);

    next();
});
```
Такой подход решает проблему на уровне сервера, инструктируя браузер пропустить запрос.

## 4. Работа с XHR и Fetch API

В JavaScript существует два основных нативных способа отправки сетевых запросов:

**1. XMLHttpRequest (XHR)** — старый способ, работающий на основе событий и коллбеков.
```javascript
const xhr = new XMLHttpRequest();
xhr.open('GET', 'http://localhost:3000/stocks');
xhr.onload = function() {
    if (xhr.status === 200) {
        const data = JSON.parse(xhr.responseText);
        // Отрисовка
    }
};
xhr.send();
```

**2. Fetch API** — современный стандарт, основанный на Промисах (Promises) и синтаксисе `async/await`. Он делает код асинхронных операций линейным и легко читаемым.

В нашем приложении был выбран `Fetch` для получения списка классов кораблей в `MainPage`:
```javascript
async loadData() {
    try {
        const response = await fetch('http://localhost:3000/stocks');
        if (!response.ok) throw new Error('Ошибка сети');
        const data = await response.json();
        return data; // Возвращаем массив классов кораблей кораблестроительного производства
    } catch (error) {
        console.error("Ошибка при загрузке данных:", error);
        return [];
    }
}
```

## 6. Реализация CRUD-операций на клиенте

Чтобы форма не просто отрисовывалась, но и отправляла данные на сервер, используется перехват события `submit`.
Метод `e.preventDefault()` предотвращает стандартную перезагрузку страницы браузером.

### Create (POST-запрос)
После заполнения формы собирается JSON-объект и отправляется методом `POST`:
```javascript
async handleFormSubmit(e) {
    e.preventDefault(); // Отменяем перезагрузку страницы

    // Собираем данные из полей ввода
    const payload = {
        src: document.getElementById('input-src').value,
        name: document.getElementById('input-name').value,
        description: document.getElementById('input-desc').value
    };

    // Отправляем POST запрос к API
    await fetch('http://localhost:3000/stocks', {
        method: 'POST',
        headers: { 'Content-Type': 'application/json' },
        body: JSON.stringify(payload)
    });

    // Возвращаемся на главную страницу после успешного сохранения
    const mainPage = new MainPage(this.parent);
    mainPage.render();
}
```

### Delete (DELETE-запрос)
В компоненте карточки (`ProductCardComponent`) на кнопку «Удалить сразу» был навешен слушатель, который отправляет запрос на удаление карточки по её ID:
```javascript
async deleteItem(id) {
    await fetch(`http://localhost:3000/stocks/${id}`, {
        method: 'DELETE'
    });

    // Заново перерисовываем главную страницу, чтобы актуализировать список
    this.render();
}
```

## 7. Дополнительные задания и модификации

В рамках работы функционал был расширен для повышения удобства:

1. **Режим редактирования (Update / PATCH):** Класс `CreateProductPage` был спроектирован так, чтобы принимать опциональный параметр `editData`. Если в форму передаются готовые данные, она работает не в режиме создания (POST), а в режиме обновления. Форма автоматически предзаполняет поля `input.value = editData.name`, а при отправке делает `PATCH http://localhost:3000/stocks/${editData.id}`.
2. **Связка с кнопками на главной:** На главной странице добавлена кнопка "Добавить классов кораблейу", которая инициирует `new CreateProductPage(this.parent).render()`. Аналогично на каждой карточке классов кораблейи была добавлена кнопка "Редактировать", прокидывающая объект карточки в ту же форму.
3. **Обработка ошибок:** Если бэкенд выключен (порт 3000 недоступен), метод `loadData()` отлавливает ошибку через блок `catch` и показывает пользователю на экране красивое предупреждение компонентом `AlertComponent` ("Не удалось связаться с сервером").
